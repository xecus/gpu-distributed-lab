# A02 — 自作Transformerの単一GPU学習

GPU：1。実行場所：承認済みAWS GPUホスト、リポジトリroot。

## 1. 理論・アルゴリズム

自作因果Transformerのforward、cross-entropy、backward、AdamWを追う。Attentionはsoftmax(QKᵀ/√d)V、lossは平均の次トークン負の対数尤度。訓練用の構造化合成列はx[t+1]=(x[t]+1) mod 256で、ランダムなラベルではないためloss低下を確認できる。
FP32で重み/stateを保持しBF16 autocastで演算する。zero_grad→forward→loss.backward→optimizer.stepの順番と、最初のAdam stepでstateが生成されることを確認する。

共通の数式・メモリモデル：[theory.md](../theory.md)。

## 2. Pythonコード

実装：`lab/model.py / lab/train.py`。ブラックボックス化せず、forward・勾配・通信・計測の位置を確認して実行する。
`lab/train.py`の`batch()`、`update()`、`checkpoint()`が学習・測定・保存の共通実装。

## 3. AWS実行コマンド

先に[aws.md](../aws.md)を完了し、`source .venv/bin/activate`。GR00T workerのみ公式uv環境。

```bash
bash scripts/part_a.sh A02 --steps 100 --batch 2 --seq 256 --dim 256 --layers 4
python scripts/summary.py runs/A02 --node-hourly-usd "$NODE_HOURLY_USD" --wall-seconds ACTUAL_SECONDS
```

## 4. 測定・CSV

metrics_rank0_from0.csvのloss、step_s、tokens_s、allocated/reserved。seq256→512→1024、dim256→512→1024のいずれか一変数だけを変える。

[measurement.md](../measurement.md)の定義で記録。`results/experiment_results.csv`に条件・status・実測値を残す。未実行値は空欄。

## 5. 期待結果

lossが初期のlog(256)≈5.55付近から低下し、最初のAdam更新後にメモリが増える。合成タスクの学習成功は自然言語の能力を意味しない。

ここは検証前の仮説であり、GPUの実測値ではない。各条件でwarmupを除き、同じ条件を再試行してばらつきを確認する。

## 6. 考察課題

1. ForwardとBackwardとAdamのどこでVRAMが増えるか。
2. sequenceを2倍にしたとき、演算・activation・tokens/sはどう変わるか。
3. Gradientが存在することと学習が進むことの違いは何か。
