# B05 — GR00T N1.7：16〜40GPU対応確認・スケーリング

GPU：16〜40。実行場所：承認済みAWS GPUホスト、リポジトリroot。

## 1. 理論・アルゴリズム

公式launch_finetuneは単一node向け説明だが、調査した現行experiment.runはtorchrunのWORLD_SIZE/LOCAL_RANKを読みprocess groupを初期化する。config.num_gpusはlocal GPU数ではなくglobal worldと一致させる必要がある。
この事実だけではdataset sharding、全rank保存、resume、global batch、EFA利用のmulti-node検証済みを意味しない。B05は対応監査と短い動作試験も実験の一部。未確認なのに40GPU本番を始めない。

共通の数式・メモリモデル：[theory.md](../theory.md)。

## 2. Pythonコード

実装：`scripts/groot_audit.py / scripts/groot_run.py / 公式experiment.py`。ブラックボックス化せず、forward・勾配・通信・計測の位置を確認して実行する。

先に[公開モデル・データ準備](../data_and_real_models.md)を実施する。

## 3. AWS実行コマンド

先に[aws.md](../aws.md)を完了し、`source .venv/bin/activate`。GR00T workerのみ公式uv環境。

```bash
python scripts/groot_audit.py --repo third_party/Isaac-GR00T
# audit結果を読み、短い16GPU動作検証へ進むためのチェック完了を明示
export NNODES=2 MASTER_ADDR=REVIEWED_NODE0_PRIVATE_IP RUN_ID=B05-smoke
# NODE_RANK=0/1を両nodeで設定。同じ絶対パス・データ・モデルsnapshotを使う
bash scripts/part_b.sh B05 --allow-multinode-smoke --steps 2 --batch 32 --out runs/B05-smoke
# 保存が揃った後、同じoutで再開。全nodeで実行
bash scripts/part_b.sh B05 --allow-multinode-smoke --steps 4 --batch 32 --out runs/B05-smoke --resume
```

## 4. 測定・CSV

WORLD_SIZE=16の実際のworker数、各rank異なるepisode/window、effective batch、loss、checkpoint/resume、NET/OFI、CPU RAMを確認。static gate passとruntime verifiedを別記録。16GPU確認後40GPUはbatch80等のworldで割り切れる値で実行。

[measurement.md](../measurement.md)の定義で記録。`results/experiment_results.csv`に条件・status・実測値を残す。未実行値は空欄。

## 5. 期待結果

対応条件が揃えば16GPU実行が可能な構造を確認。実測がないため40GPUの速度は保証しない。unsupported/blockedもstatusとして残す。VLAはvideo decode/CPU I/Oがスケーリングを制限しうる。

ここは検証前の仮説であり、GPUの実測値ではない。各条件でwarmupを除き、同じ条件を再試行してばらつきを確認する。

## 6. 考察課題

1. num_gpus=8のまま16rankで起動すると何が壊れるか。
2. 全nodeが同じepisodeを読む場合、速度が良くても有効な分散学習か。
3. 40GPUへ増やす前に最低限何を確認・承認するか。

成果物：実行command／environment／CSV／失敗log／checkpoint（学習実験）／短い考察。終了時はmonitor停止・全rank保存・instance終了・残存費用確認を行う。
