# B04 — GR00T N1.7：8GPU VLA Fine-tuning・Action評価

GPU：8。実行場所：承認済みAWS GPUホスト、リポジトリroot。

## 1. 理論・アルゴリズム

GR00T N1.7は言語・画像・状態からaction chunkを出すVLA。次トークンlossのQwen実験とaction生成lossは別。最初は公式デモの5episodeで配線/学習を確認し、その後に製造・物流の自社データへ進む。
データはGR00T-flavored LeRobot形式、modalityにはcamera/state/action/languageキーとhorizonを定義。camera timestamp、関節/EEF座標、単位、相対actionとgripper絶対actionの区別が重要。

共通の数式・メモリモデル：[theory.md](../theory.md)。

## 2. Pythonコード

実装：`scripts/groot_run.py / groot_entry.py / groot_eval.py / groot_csv.py`。ブラックボックス化せず、forward・勾配・通信・計測の位置を確認して実行する。

先に[公開モデル・データ準備](../data_and_real_models.md)を実施する。

## 3. AWS実行コマンド

先に[aws.md](../aws.md)を完了し、`source .venv/bin/activate`。GR00T workerのみ公式uv環境。


## 4. 測定・CSV

Trainer loss、global batch、all-GPU peak、samples/s/壁時計、Action MAE/MSE、予測/GT plot。公式デモ上の誤差はfit確認でありheld-out評価ではない。自社データはepisode/session/taskで分離する。

[measurement.md](../measurement.md)の定義で記録。`results/experiment_results.csv`に条件・status・実測値を残す。未実行値は空欄。

## 5. 期待結果

demoのtraining trajectoryでloss/action誤差が低下する傾向。5episodeでは過学習・未知タスクの低性能は自然。VLAの速度指標はsamples/sとaction chunk/sを用いLLM tokens/sと混ぜない。

ここは検証前の仮説であり、GPUの実測値ではない。各条件でwarmupを除き、同じ条件を再試行してばらつきを確認する。

## 6. 考察課題

1. 正規化lossは小さいのに実単位のAction MAEが大きい理由は何か。
2. 相対EEF座標と関節角の単位/基準系は一致しているか。
3. Open-loop誤差低下から実機成功率を直接推定できるか。

成果物：実行command／environment／CSV／失敗log／checkpoint（学習実験）／短い考察。終了時はmonitor停止・全rank保存・instance終了・残存費用確認を行う。
