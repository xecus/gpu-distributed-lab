# A12 — Attention・MLP Tensor Parallelism

GPU：2〜8。実行場所：承認済みAWS GPUホスト、リポジトリroot。

## 1. 理論・アルゴリズム

Q/K/V Linearの出力方向を分割し、各rankがlocal attention headsを計算する。出力projectionは入力方向を分割してpartial outputをAllReduce。MLPもfc1をColwise、fc2をRowwiseにする。
replicated hidden→Colwise→local head/expanded dimension→Rowwise＋AllReduce→replicated hidden、という流れ。Embedding/LayerNorm/LM headは複製。total_headsとdimはTP sizeで割り切れる設定にする。全rankが同じ入力サンプルとtargetを使う。

共通の数式・メモリモデル：[theory.md](../theory.md)。

## 2. Pythonコード

実装：`lab/model.py：apply_tp / lab/tp_check.py`。ブラックボックス化せず、forward・勾配・通信・計測の位置を確認して実行する。
`lab/train.py`の`batch()`、`update()`、`checkpoint()`が学習・測定・保存の共通実装。

## 3. AWS実行コマンド

先に[aws.md](../aws.md)を完了し、`source .venv/bin/activate`。GR00T workerのみ公式uv環境。

```bash
NPROC=2 bash scripts/launch.sh lab.tp_check
for n in 2 4 8;do
 NPROC=$n bash scripts/part_a.sh A12 --dim 1024 --layers 12 --heads 8 --seq 512 --batch 2 --accum 1 --out runs/A12/tp${n}
done
```

## 4. 測定・CSV

tp_checkでforward/gradient/SGD更新をunshardedモデルと比較。TPのglobal_batchにworldを掛けていないことをCSVで確認。memory、GEMMサイズ、layer内通信を測る。

[measurement.md](../measurement.md)の定義で記録。`results/experiment_results.csv`に条件・status・実測値を残す。未実行値は空欄。

## 5. 期待結果

Attention/MLPの重みと演算を分割できるが、複製したEmbedding/headとactivationは残る。小GEMMが増えると高速化しない。ノード内NVSwitchでまず比較する。

ここは検証前の仮説であり、GPUの実測値ではない。各条件でwarmupを除き、同じ条件を再試行してばらつきを確認する。

## 6. 考察課題

1. TPで各rankに異なるサンプルを与えるとどうなるか。
2. MLPのfc1とfc2の間にAllGatherが不要な理由は何か。
3. TPとDPを同時に使うならdata rankとTP groupをどう分けるか。
